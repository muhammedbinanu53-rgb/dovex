# DoveX free deployment notes

The backend supports local JSON storage for development and Supabase for cloud storage. With Render's free service configured below, database data lives in Supabase Postgres and product images live in Supabase Storage. Do not add a Render disk or paid plan.

## 1. Create the free Supabase project

1. Create a Supabase project on the Free plan: https://supabase.com/dashboard
2. Open **SQL Editor** and run `supabase-setup.sql` from this repository.
3. In **Project Settings → API**, copy the project URL and the `service_role` key. Keep the service role key private. Never put it in frontend/Vercel variables or commit it to GitHub.

## 2. Deploy the backend on Render Free

1. Cancel the payment/card prompt; do not create a paid Blueprint service.
2. In Render, create a new Blueprint from `muhammedbinanu53-rgb/dovex`, branch `main`, Blueprint path `render.yaml`.
3. The Blueprint uses `plan: free`, has no disk, and asks for these values:
   - `ADMIN_EMAIL`: your private admin email
   - `ADMIN_PASSWORD`: a private password with at least 12 characters
   - `FRONTEND_URL`: the exact deployed Vercel origin, e.g. `https://dovex-three.vercel.app` (no trailing slash)
   - `SUPABASE_URL`: your Supabase project URL
   - `SUPABASE_SERVICE_ROLE_KEY`: your private service role key
4. Leave `JWT_SECRET` generated by Render and keep `SUPABASE_STORAGE_BUCKET` as `product-images`.
5. Deploy. The backend starts with an empty DoveX cloud database and creates the initial admin from the Render environment variables.

Free Render services sleep after 15 minutes without traffic and may take about a minute to wake. Render's free filesystem is temporary, so the deployed backend must use Supabase. Supabase Free projects can pause after a week with very little activity. These free services have limits and are suitable for trying the deployment, not a guaranteed always-on production marketplace.

## 3. Point Vercel to the backend

In the Vercel project serving your frontend, set `VITE_API_URL` to the Render service origin, for example `https://dovex-api.onrender.com` (no trailing slash), then redeploy the frontend. Use the actual hostname shown by Render.

## Local development

If `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` are both absent, the backend keeps using its local JSON database and local uploaded files. If only one Supabase variable is set, startup fails rather than silently using local storage.
